= When Polaris's PAPI answers with an error
:description: How DCB reads the error codes in a PAPI answer, and the one answer it reads as "no match".

Polaris's PAPI answers most failures with HTTP 200 and a negative `PAPIErrorCode` in the body. A
positive code is a count of rows; 0 is success.

DCB treats every negative code as a failure, with one exception below.

== Patron blocks

When DCB reads a patron's circulation blocks and PAPI answers -1 ("General failure"), DCB now
fails the patron lookup. Before this release DCB read the -1 as "not blocked", so a patron PAPI
could not check was let through.

If a Polaris answers -1 for every blocks check, its patrons cannot place requests until the
cause is fixed. The error names the code and PAPI's message.

== The virtual patron search

When DCB searches for its virtual patron for a borrower, PAPI answers a search with no match with
-1, an empty `ErrorMessage` and no rows (seen on the Polaris 8.1 training server, 2 Nov 2026). DCB
reads that answer, and only that answer, as "no match" and creates a virtual patron.

Any other -1, for example one with the message "General Failure", fails the search. Before this
release DCB read every -1 as "no match", so a search that failed created a second virtual patron
for the same borrower.

If a Polaris version words its "no match" answer differently, DCB cannot create new virtual
patrons there, and the error names the code and PAPI's message.
