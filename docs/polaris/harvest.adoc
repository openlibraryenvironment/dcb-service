= Harvesting a Polaris catalogue
:description: How DCB's PAPI harvest walks a Polaris catalogue, where it resumes, and what it does not pick up.

By default DCB harvests a Polaris catalogue through PAPI. (A Host LMS can be switched to OAI-PMH
instead; see the Polaris notes for that.)

== Full harvest, then changes

The first harvest walks every bib by id. After that, each run asks Polaris for the bibs modified
since a watermark, and walks those ids in pages. A run that stops part-way resumes from the last
id it reached.

== The watermark

When a walk finishes, DCB sets the next watermark to the earlier of:

* the newest modification date it saw in the walk, and
* the moment the walk began, by DCB's clock,

less `harvest-watermark-overlap-minutes` (default 15). The overlap is re-harvested on every run,
so keep it small.

Taking the start of the walk matters for a long walk. A bib edited while the walk runs, but behind
the walk's cursor, carries a date older than the newest date the walk saw. Before this release
the watermark could pass it, and the edit was never harvested.

Whether Polaris reports modification dates in UTC or in the server's local time has not been
checked against a Polaris server. Because the watermark can only move earlier, not later, a
difference costs extra re-harvesting rather than lost edits.

== When a row cannot be read

If DCB cannot read a bib from a harvested page, it logs `POLARIS_HARVEST_UNSTAGED` with the bib id
and raises the alarm `ILS.<host LMS code>.POLARIS_HARVEST_UNSTAGED`, which lists up to 100 bib
ids. The walk moves past the row, so the bib is not harvested again until it changes in Polaris.
Run the reconcile (`POST /admin/sourceImport/<code>/reconcile`) once the cause is fixed.

== Deleted bibs

When a walk finishes, DCB asks Polaris which bibs were deleted since its deletions watermark, and
removes each one from DCB. It asks at most every 30 minutes, reads at most 20 pages of 100 ids in
one run (a run that hits the cap carries on from where it stopped next time), and logs
`POLARIS_HARVEST_DELETIONS` with how many it found.

The first time, DCB reads deletions from the last 90 days. A bib deleted in Polaris before that
stays in DCB until a reconcile or, on the OAI-PMH harvest, the vanished-bib sweep removes it.

If Polaris does not answer, the update harvest carries on and DCB asks again on the next run.
