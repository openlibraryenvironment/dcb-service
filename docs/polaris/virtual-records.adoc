= Virtual bibs and items in Polaris
:description: What DCB creates in a borrowing library's Polaris for a request, and the checks it makes.

When a Polaris library borrows from another library, DCB creates a virtual bib and a virtual
item in that library's Polaris, and places the patron's hold on the virtual item.

== The virtual bib is hidden from the PAC

DCB creates the virtual bib with *Display in PAC* off and *Do not overlay* on. It carries the
title (245 $a) and the source record's material type in leader position 06.

Polaris can answer the create with the id of a bib it already had, presumably through its
duplicate detection. If that bib is displayed in the PAC, a holdable virtual item attached to it
joins the bib's local hold queue: on return, it traps for the next local hold, and a local patron
is told an item is ready that must go back to another library.

So DCB reads the bib back after creating it. Unless Polaris reports it as *not* displayed in the
PAC, DCB stops: it attaches no item, and the request errors with "Polaris did not create a hidden
virtual bib", naming the bib id. Staff should check that bib in Polaris.

DCB also stops if it cannot read the bib back.

== Deleting the virtual item

When a request finishes, DCB deletes the virtual item through the Application Services delete
item workflow. Polaris refuses to delete an item that a loan or hold still links to. It reports
that by listing the item as blocked while still answering that the workflow completed.

DCB now records that case in the request's audit as "Delete virtual item : Failed", with the
detail "Polaris refused to delete the virtual item". Earlier releases recorded it as a success,
so the item stayed in the catalogue unnoticed. Staff should delete it by hand once its loan or
hold has gone.

DCB deletes with `IsAutoDelete` false, so Polaris soft-deletes the item. Whether a soft-deleted
item keeps its barcode, which would make Polaris refuse the next virtual item with that barcode
(prompt 72, "duplicate barcode"), has not been checked against a Polaris server. The Host LMS
setting `enableDoubleDelete` exists but is not read anywhere yet.

== When several virtual patrons match

DCB finds the borrowing patron's virtual patron at a Polaris lender by searching Polaris. If more
than one patron matches:

* If any match lacks the virtual patron barcode prefix (`services.patron-barcode-prefix`, default
`DCB-`), it is a real patron. DCB refuses, and the request's audit says "Virtual patron : multiple
found", with the reason. Staff should resolve the match in Polaris.
* Otherwise DCB uses the virtual patron it used last for this borrower, and records a warning in
the request's audit naming the others by their Polaris patron id, to merge or delete.
* If DCB has used none of them, it refuses as before.

== Removing virtual patrons

DCB never removes a virtual patron on its own: libraries expect them to stay. Staff can ask DCB to
remove one, or every one a borrower has:

* `POST /patrons/identities/{identityId}/virtual/retire`, with an optional body
`{"mode": "DELETE"}` or `{"mode": "EXPIRE"}`
* `POST /patrons/{patronId}/virtual-identities/retire`, one library system at a time, with an
outcome for each

A library system that can delete a patron (Sierra, Alma, Koha) deletes it, and DCB then forgets its
own record: finished requests no longer name that virtual patron. Polaris cannot delete a patron,
so DCB sets its expiry date to yesterday and keeps its record; DCB renews it if the borrower
requests from that library again. FOLIO is not supported.

DCB refuses:

* the patron's own library account, and any record that is a patron's own account in that system;
* a borrower with any request that is not yet finalised;
* a record the library's system does not name as DCB's virtual patron for that borrower, or one
of several it might be;
* in Polaris, a patron whose barcode does not start with the virtual patron barcode prefix.

Consortium staff can remove any virtual patron. A library administrator can remove the virtual
patrons of their own library's borrowers, and a single virtual patron held in their library's
system. Each removal is recorded in the event log, with the member of staff, and is limited to 10
a minute for each member of staff (`dcb.requests.virtual-patron-removal.per-caller-per-minute`).
